# Rubric ประเมินความยาก

ให้คะแนน 0–2 ต่อข้อ ตอบจากสิ่งที่เห็นได้ก่อนลงมือ ไม่ใช่จากความรู้สึกว่ายาก

| เกณฑ์ | 0 | 1 | 2 |
|---|---|---|---|
| ความชัดของ spec | บอกครบว่าทำอะไร ที่ไหน | ต้องตีความบางจุด | ต้องตัดสินใจเองเยอะ |
| ขอบเขต | ไฟล์เดียว | 2–3 ไฟล์ในโมดูลเดียว | ข้ามหลายโมดูล |
| มีแบบให้ดู | มีโค้ดคล้ายกันในโปรเจกต์ | มีบางส่วน | ของใหม่ทั้งหมด |
| ตรวจได้ง่ายไหม | มี test ครอบคลุม | ตรวจด้วยมือได้ | ตรวจยาก ต้องคิดตาม |
| ความเสี่ยง | พังแล้วแก้ง่าย | กระทบส่วนอื่นบ้าง | ข้อมูลเสียหายหรือมีช่องโหว่ |

## แปลงคะแนนเป็นโมเดล

| คะแนนรวม | โมเดล |
|---|---|
| 0–3 | Haiku |
| 4–6 | Sonnet |
| 7–10 | Opus |

## กฎบังคับ (ข้ามคะแนน)

1. แตะ auth, crypto, การจัดการสิทธิ์ หรือการรับ input จากผู้ใช้ → **Opus เสมอ**
2. ย้อนกลับไม่ได้ (migration, ลบข้อมูล, เปลี่ยน schema) → **Opus** และหยุดถามผู้ใช้ก่อนรัน
3. "ความชัดของ spec" ได้ 2 → **ไม่ส่งงาน** กลับไปถามผู้ใช้ก่อน
4. "ตรวจได้ง่ายไหม" ได้ 2 → ปัดขึ้นหนึ่งขั้น เพราะถ้าประเมินพลาด งานผิดอาจผ่านไปโดยไม่มีใครเห็น

## การปรับเกณฑ์

ช่วงคะแนนข้างบนเป็นจุดเริ่มต้น ไม่ใช่ค่าที่พิสูจน์แล้ว
ดู `.claude/router-log.md` เป็นระยะ ถ้าคะแนนช่วงไหนโดนตีกลับบ่อย ให้ขยับเส้นแบ่งแล้วแก้ไฟล์นี้
